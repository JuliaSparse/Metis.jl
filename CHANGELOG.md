# Metis.jl changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [v1.7.0] - 2026-11-24
### Added
 - `Metis.Options` for setting Metis options, passed to `Metis.partition`,
   `Metis.permutation` and `Metis.separator` with the new `options` keyword argument, e.g.
   `Metis.partition(G, 4; options = Metis.Options(seed = 42))`. This replaces modifying the
   global `Metis.options` array, which is error-prone since it is shared by the whole
   process. With `options`, the global array isn't used, and options that aren't set get the
   Metis defaults. An `Options` can also be passed directly to the C API functions ([#52],
   [#82]).
 - `Metis.Algorithm` enum for the `alg` keyword argument of `Metis.partition`, e.g.
   `Metis.partition(G, 4; alg = Metis.Algorithm.RECURSIVE)` ([#83]).

### Deprecated
 - Passing the `alg` keyword argument of `Metis.partition` as a symbol (`:KWAY` or
   `:RECURSIVE`) is deprecated in favour of `Metis.Algorithm`. Symbols still work, but give
   a deprecation warning ([#83]).
 - Setting options in the global `Metis.options` array for `Metis.partition`,
   `Metis.permutation` and `Metis.separator` is deprecated in favour of `Metis.Options`.
   Without the `options` keyword argument, options set there are still used, but give a
   deprecation warning. `Metis.options` itself is deprecated too: use a `Metis.Options` also
   when calling the C API directly. It is only kept since existing code refers to it, and
   will be removed in the next breaking release ([#82]).

### Changed
 - Julia 1.10 is now required. Graphs.jl and LightGraphs.jl are no longer dependencies of
   Metis.jl: support for them is only loaded, as package extensions, when they are loaded
   ([#81]).

## [v1.6.0] - 2026-11-24
This release validates input that Metis can't handle, and throws an `ArgumentError` for it
instead of passing it to Metis, where it could crash, hang or give invalid results. Some
calls that ran before therefore throw now; see the entries under Changed.

### Added
 - `Metis.graph` now checks that the graph is symmetric, which Metis requires: every edge
   must be stored in both directions, with the same weight in both directions when weights
   are used. This applies to sparse matrices and to directed Graphs.jl, LightGraphs.jl and
   SimpleWeightedGraphs.jl graphs. The check can be skipped with the new `check = false`
   keyword argument ([#78]).
 - `Metis.partition`, `Metis.permutation` and `Metis.separator` can now be called from
   several threads at once, also with the same `Metis.Graph`. The calls to Metis are
   serialized with a lock, since Metis has global state ([#77], [#79]).

### Changed
 - The `check_hermitian` keyword argument of `Metis.graph(::SparseMatrixCSC)` is deprecated
   in favour of `check`. Instead of requiring a Hermitian matrix, `check = true` requires a
   symmetric pattern of stored entries, and symmetric values only with `weights = true`. A
   matrix with a symmetric pattern but unsymmetric values is therefore now accepted without
   weights, and a matrix with a one-sided stored zero is now rejected (remove such entries
   with `SparseArrays.dropzeros`) ([#78]).
 - Directed graphs with a one-way edge, or with different weights in the two directions
   when weights are used, now throw an `ArgumentError` in `Metis.graph`, and therefore also
   in `Metis.partition`, `Metis.permutation` and `Metis.separator` ([#78]).
 - Edge weights that aren't positive integers now throw an `ArgumentError` in
   `Metis.graph`, including zero weights from stored zeros in a sparse matrix. Previously
   zero and negative weights were passed to Metis, and fractional weights threw an
   `InexactError` ([#73]).
 - `Metis.partition` now throws an `ArgumentError` for an unknown `alg`, for fewer than 1
   part, and for more parts than vertices (except 1 part for a graph without vertices)
   ([#75]).
 - `Metis.graph` now throws an `ArgumentError` for a non-square matrix ([#70]) and a
   `MethodError` for unknown keyword arguments for graph types ([#71]).
 - Metis no longer modifies the `xadj` and `adjncy` arrays of a `Metis.Graph` during a
   call. The global `Metis.options` is unchanged and still uses 1-based numbering
   ([#79]).

### Fixed
 - Edge weights are no longer swapped in the conversion from a directed
   SimpleWeightedGraphs.jl graph ([#56], [#57]).
 - `Metis.graph(G; weights = true)` for Graphs.jl and LightGraphs.jl graphs now gives unit
   weights instead of throwing an `UndefVarError` ([#74]).
 - `Metis.permutation` and `Metis.separator` no longer require valid edge weights for
   SimpleWeightedGraphs.jl graphs, since they don't use them ([#72]).
 - `Metis.separator` now works for a `Metis.Graph` without edges with `adjncy = C_NULL`
   ([#79]).
